# 04 Parquet And DuckDB

Parquet is the handoff from ingestion to analytics. In the production-style workflow, the first Parquet contract is the bronze byte layer:

```text
lake/bronze/raw_assets.parquet
lake/bronze/raw_asset_chunks/part-*.parquet
lake/bronze/metadata_records.parquet
```

`raw_assets.parquet` is the inventory. `raw_asset_chunks/part-*.parquet` contains ordered binary chunks that can reconstruct every raw file. `metadata_records.parquet` preserves every row from every nuScenes metadata JSON table, even when no curated table has been modeled yet.

Run:

```bash
make query-demo
```

The query demo uses DuckDB through Python to read Parquet tables generated by Go. It checks sample counts, sensor channels, raw byte coverage, metadata table coverage, and LiDAR feature rows.

Go and data concepts:

- explicit artifact boundaries
- byte-level provenance and SHA-256 checksums
- columnar storage
- local analytics without a database server

Reference exercise: add a DuckDB query that compares `sum(size_bytes)` from `raw_assets.parquet` with `sum(size_bytes)` from `raw_asset_chunks/*.parquet`.
